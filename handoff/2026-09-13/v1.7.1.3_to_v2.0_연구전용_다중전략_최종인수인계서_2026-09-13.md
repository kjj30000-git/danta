### 1.2 v2.0의 목적

v2.0은 주문속도 개선 버전이 아니라 **연구 운영체계 전환 버전**이다.

1. 실제매매와 키움 모의투자를 모두 하지 않는다.
2. 내부 가상매매와 원본 데이터 수집만 수행한다.
3. 기존 전략을 대조군으로 일부 유지하되 약한 전략의 신규 진입은 중단한다.
4. 같은 시세에서 성격이 다른 전략들을 병렬 실행해 비교한다.
5. 주문엔진의 남은 속도·미체결 과제는 동결해 별도 후속 버전으로 미룬다.

## 2. 실행 모드 확정

### 2.1 첫 셀의 단일 명시 설정

Boolean 조합 대신 다음 문자열 하나를 사용한다.

```python
EXECUTION_MODE = "RESEARCH"  # "RESEARCH" / "MOCK" / "LIVE"

AUTO_TRADE_ENABLED = EXECUTION_MODE in {"MOCK", "LIVE"}
USE_MOCK = EXECUTION_MODE == "MOCK"
```

- v2.0 release 저장 기본값과 2026-09-14 실행값은 반드시 `"RESEARCH"`다.
- `RESEARCH`: 내부 가상매매·데이터 수집만 실행하고 broker 주문은 호출하지 않는다.
- `MOCK`: 향후 키움 모의주문 연결용 예약값이다. 이번 운영에서는 선택하지 않는다.
- `LIVE`: 향후 실제주문 연결용 예약값이다. 이번 운영에서는 선택하지 않는다.
- 사용자 결정에 따라 확인문구, 두 번째 Boolean, 이중차단 UI는 추가하지 않는다.
- mode 문자열을 별도 validator로 강제하지 않는다. 오타나 미지원값은 위 파생식상 주문 OFF가 되어야 한다.
- 기존 함수들이 참조하는 `AUTO_TRADE_ENABLED`, `USE_MOCK` 이름은 호환을 위해 파생값으로 유지한다.

### 2.2 주문엔진 처리

- v1.7.1.3의 주문 우선순위, 수량·중복방지, cache/REST fallback, 미체결 관리, watchdog, 상태복구 함수는 삭제하거나 재작성하지 않는다.
- `RESEARCH`에서는 주문경로가 호출되지 않아야 한다.
- 주문엔진의 추가 개선과 키움 모의·실제 주문 검증은 보류한다.
- 보류 과제: 청산 전 broker 사전조회 지연, cache 신선도, 부분·장기 미체결, 주문 응답 불명 상태, 실제 broker에서의 priority/watchdog 검증.
- 주문 모드를 다시 사용할 때는 이 보류 과제를 재개하고 별도 승인을 받아야 한다.

## 3. 반드시 수정할 시간기록 오류

v1.7.1.3의 2026-09-11 BUY 알림/최종 CSV는 `signal_to_order_sec`를 실제 주문접수까지가 아니라 API 시작까지로 표시했다.

예를 들어 삼화콘덴서는 신호 09:09:15.378, API 시작 09:09:18.341, 주문접수 09:09:19.133이므로:

- 신호→API 시작: 2.963초
- 신호→주문접수: **3.755초**
- 신호→최종체결: 3.802초

바이오니아는 신호→API 시작 2.860초가 아니라 신호→주문접수 **4.021초**가 맞다.

수정 원칙:

- `signal_to_order_sec = order_accepted_at - signal_time`
- `trigger_to_order_sec = order_accepted_at - trigger_time`
- `api_slot_wait_ms = api_slot_acquired_at - api_slot_requested_at`
- `http_duration_ms = order_accepted_at - api_started_at`
- `accepted_to_first_fill_sec = first_fill_at - order_accepted_at`
- `accepted_to_final_fill_sec = final_fill_at - order_accepted_at`
- `total_duration_sec = final_fill_at - signal_time/trigger_time`
- 표시 시각은 timezone-aware `datetime`, 구간 측정은 `time.monotonic()`을 계속 사용한다.
- CSV, Telegram, 메모리 주문원장의 같은 필드가 동일 정의를 사용하게 한다.
- 과거 CSV를 소급 수정하지 않는다. v2.0 이후 신규 기록부터 수정한다.

이 수정은 `RESEARCH` 운용 중 실제 주문을 시험하라는 뜻이 아니다. 정적 산식 단위시험과 mock 이벤트 회귀시험으로 검증한다.

## 5. 신규 주식 전략 정의

### 5.1 공통 원칙

- 모든 신규 전략은 가상매매 전용이다.
- 동일 tick/스냅샷을 공유하되 전략별 독립 `trade_id`, 상태, 진입·청산 결과를 가진다.
- 진입 당시 알 수 있는 값만 사용한다. MFE, MAE, 최종 청산결과 등 미래정보를 진입조건에 사용하지 않는다.
- 각 전략의 조건 통과/실패 이유를 `paper_entry_decisions`에 기록한다.
- 전략명·`rule_version`·진입조건 원시값을 저장해 조건 변경 전후 표본을 섞지 않는다.

### 5.2 `CALM_FIRST_75`

기존 표본에서 발견된 작은 가설을 전향적으로 검증하는 전략이다. 과최적화된 승격전략으로 취급하지 않는다.

초기 연구조건:

```text
FIRST_75_PASS
AND 0.05% <= price_change_30s <= 0.60%
AND price_change_60s <= 1.70%
AND high_gap_change_60s > -0.40%p
```

- 기존 분석 표본: 9건, 승률 55.6%, net 평균 +0.493%, PF 1.62.
- 최근 구간 표본은 3건뿐이므로 실전 승격 근거가 아니다.
- 30초·60초 실제 관측 간격과 history 유효성도 함께 기록한다.
- 조건 미충족이면 BASE/FIRST_75 대조군에는 영향 없이 CALM만 SKIP한다.

### 5.3 `CALM_FIRST_75_PROTECT`

- 진입은 `CALM_FIRST_75`와 동일하다.
- +1.00% 도달 시 arm, 이후 +0.40% 이하로 밀리면 가상청산한다.
- 기본 TP/SL과 보호청산 중 먼저 발생한 이벤트를 사용한다.
- CALM 본체와 같은 진입시각·진입가를 가져야 하며 진입 차이로 성과가 섞이면 안 된다.
- 보호정책이 손절을 줄였는지와 TP를 놓쳤는지를 모두 기록한다.

### 5.4 ORB 계열 공통 정의

- ORB는 기존 75점 전략과 독립된 universe와 상태를 사용한다.
- 초기 universe는 09:00 직후 실제 거래대금 순위에서 ETF·우선주·관리/제외종목을 제거한 상위 20종목으로 고정한다. `ORB_UNIVERSE_SIZE = 20`을 첫 셀에 노출한다.
- universe 확정 뒤 종목을 교체해 유리한 표본만 선택하지 않는다. 범위 완성에 필요한 관측이 부족한 종목은 진입시키지 않고 결측으로 남긴다.
- 09:00:00~09:04:59의 관측 가격으로 opening range high/low를 구성한다.
- 09:05:00 이후에만 진입 판정하며 `opening_range_complete=True`가 아니면 진입하지 않는다.
- `opening_range_complete`는 첫 유효 관측이 09:00:30 이전, 마지막 유효 관측이 09:04:45 이후이고 관측 공백이 45초를 넘지 않을 때만 True로 한다.
- 09:00:30 이후 프로그램 시작 또는 범위를 온전히 관측하지 못한 종목은 그날 ORB 진입을 허용하지 않고 `DATA_UNAVAILABLE`로 기록한다.
- 사용자 확정 초기값은 돌파 +0.10%, retest 허용폭 범위상단 대비 ±0.15%, reclaim +0.05%, 진입 허용시간 09:05~10:30, 동일 구간 지수대비 상대강도 +0.20%p다.
- 첫 셀에 `ORB_BREAKOUT_BUFFER_PCT = 0.10`, `ORB_RETEST_TOLERANCE_PCT = 0.15`, `ORB_RECLAIM_BUFFER_PCT = 0.05`, `ORB_ENTRY_START = "09:05"`, `ORB_ENTRY_END = "10:30"`, `ORB_RS_MIN_EXCESS_PCT = 0.20`으로 노출한다.
- 위 값은 초기 연구가설이며, 2026-09-14 첫 실행 결과를 보고 소급 변경하지 않는다.

`ORB_DIRECT`:

- opening range high를 상향 돌파할 때 진입하는 대조군.
- 가짜 돌파 위험을 그대로 측정하는 기준이므로 retest 조건을 섞지 않는다.

`ORB_RETEST`:

- 상향 돌파 후 opening range high 부근으로 되돌림이 발생하고 다시 위에서 지지/회복될 때 진입한다.
- `breakout_seen_at`, `retest_seen_at`, `reclaim_seen_at`, 각 가격과 허용폭을 기록한다.
- 단순 `NEW_FIRST_PULLBACK_SHADOW`와 이름·상태·CSV 값을 공유하지 않는다.

`ORB_RS_RETEST`:

- `ORB_RETEST` 조건에 시장 proxy 대비 상대강도 조건을 추가한다.
- KOSPI 종목은 KOSPI proxy, KOSDAQ 종목은 KOSDAQ proxy를 사용한다.
- proxy가 없거나 오래됐으면 억지 추정하지 않고 `MARKET_DATA_UNAVAILABLE`로 기록한다.
- 상대강도 계산창과 proxy timestamp를 저장한다.

## 6. TP/SL 실험군

### 6.1 기존 전략

기존 전략은 연속성을 위해 부모의 169개 grid를 유지한다.

```python
TP = 1.00% ~ 4.00%, 0.25% 간격  # 13개
SL = -0.50% ~ -3.50%, 0.25% 간격 # 13개
```

### 6.2 신규 주식 전략

신규 CALM/ORB 전략은 다음 20개 조합을 사용한다.

```python
NEW_STOCK_TP_PCTS = [1.50, 2.00, 2.50, 2.75, 3.00]
NEW_STOCK_SL_PCTS = [-0.75, -1.00, -1.25, -1.50]
```

- 사용자 결정에 따라 TP +2.75%, +3.00%를 포함한다.
- 5 × 4 = 20개 결과는 20건의 독립 진입이 아니라 동일 `trade_id`의 청산 counterfactual이다.
- 강제 시간청산은 15:20을 기본으로 함께 기록한다.

## 7. ETF 장후반 모멘텀 연구

### 7.1 대상과 목적

주식의 장초반 급등 추격과 다른 시간축·논리의 전략을 검증한다. 오전 수익률/첫 30분 방향이 장 후반에도 이어지는지 국내 지수 ETF에서 전향적으로 수집한다. 해외 연구 결과를 국내 시장 성과로 간주하지 않는다.

초기 주 실행 종목:

| 역할 | 코드 | 종목 |
|---|---:|---|
| KOSPI long | `069500` | KODEX 200 |
| KOSPI inverse shadow | `114800` | KODEX 인버스 |
| KOSDAQ long | `229200` | KODEX 코스닥150 |
| KOSDAQ inverse shadow | `251340` | KODEX 코스닥150선물인버스 |

- v2.0 초기에는 레버리지 ETF를 사용하지 않는다.
- long이 본 연구군이고 하락방향 inverse는 별도 shadow로 구분한다.
- 지수별 하루 1회, 전체 최대 2회의 가상진입으로 제한한다.

### 7.2 진입·청산 비교

- 진입 후보시각: 14:30, 14:50, 15:00.
- 각 후보시각은 독립 정책 결과로 구분한다.
- 사용자 확정 진입 신호는 `09:00~09:30 수익률의 방향`과 `09:00~각 후보시각 직전 당일 누적 수익률의 방향`이 일치하는 경우다.
- 두 수익률이 모두 양수면 long ETF, 모두 음수면 inverse ETF를 해당 지수의 가상진입 대상으로 삼는다. 어느 하나가 0이거나 부호가 다르면 `NO_DIRECTION_CONSENSUS`로 SKIP한다.
- 신호 계산에는 후보시각 직전까지 확정된 가격만 사용한다. 후보시각 이후 가격으로 방향을 다시 판정하지 않는다.
- 14:30·14:50·15:00 정책은 서로 독립된 counterfactual이며, 앞 정책의 진입 여부나 결과가 뒤 정책을 차단하지 않는다. 단, 운영 요약의 고유 시장기회는 지수별 하루 1회로 별도 집계한다.
- 기본 강제청산: 15:20.
- 데이터가 늦거나 누락된 시각은 다음 시각으로 임의 대체하지 않고 결측 상태를 기록한다.

ETF 전용 청산 grid:

```python
ETF_TP_PCTS = [0.30, 0.50, 0.75, 1.00]
ETF_SL_PCTS = [-0.20, -0.30, -0.50, -0.75]
ETF_TIME_EXIT = "15:20"
```

TP/SL 16개 조합과 TIME_EXIT 기준을 모두 비교한다.

### 7.3 KODEX·TIGER·ACE 비교

초기 가상체결 기준 종목은 단기 매매의 거래량·거래대금·호가 유동성을 우선해 KODEX로 한다. TIGER와 ACE는 동일 지수 비교 관측군으로 수집한다.

```python
ETF_EXECUTION_COMPARISON_SYMBOLS = {
    "KOSPI200": ["069500", "102110", "105190"],   # KODEX, TIGER, ACE
    "KOSDAQ150": ["229200", "232080", "354500"], # KODEX, TIGER, ACE
}
```

- ACE 코스닥150 코드는 `354500`이다.
- 단기 전략에서는 연간 총보수 차이보다 실제 bid-ask spread와 체결가능 거래량의 영향이 더 클 수 있다.
- 종목별 거래량·거래대금·최우선 bid/ask·spread·iNAV 괴리·추적오차를 가능한 범위에서 기록한다.
- 동일 지수 3개 운용사 ETF 결과는 서로 독립적인 시장 표본으로 세지 않는다.
- 호가 데이터가 충분히 쌓인 뒤 KODEX보다 TIGER/ACE가 일관되게 유리하면 실행 기준 종목 변경을 별도 결정한다.

### 7.4 가상매매 비용과 체결가

- 실제 주문이 없어도 보수적으로 비용을 추정한다.
- 호가가 있으면 가상매수는 당시 최우선 매도호가, 가상매도는 최우선 매수호가를 사용해 spread를 반영한다.
- 호가가 없으면 체결가를 임의로 유리하게 만들지 말고, 기준가와 함께 최소 왕복 1 tick씩의 보수적 slippage 가정을 별도 필드로 기록한다.
- 주식용 고정 왕복비용 0.24%를 ETF에 그대로 적용하지 않는다.
- ETF 보수는 NAV에 반영되는 연간 비용이므로 20~50분 보유 거래마다 다시 차감하지 않는다.
- 계좌별 매매수수료와 ETF 과세가 정확히 확정되지 않으면 0원으로 단정하지 말고 `cost_status=UNCONFIRMED`와 gross 결과를 우선 보존한다.
- `gross_return_pct`, `commission_estimate`, `spread_cost`, `slippage_cost`, `tax_estimate`, `estimated_net_return_pct`, 각 비용 가정 버전을 저장한다.
