## 5. FIRST_75_PASS 최신 성능 판단 — 기준선

## 6. 연구와 실제매매 격리 — P0 구현 필수

### 6-1. 확인된 v1.6.10 위험

현재 `handle_realtime_price()`는 개념상 다음 순서다.

```text
capture_first_ws_tick
→ update_paper_position (169-grid 계산 및 경우에 따라 CSV 저장)
→ update_entry_path_tracking (CSV 저장 가능)
→ update_post_exit_tracking (CSV 저장 가능)
→ update_live_position_on_price
```

따라서 가상전략 계산·동기 CSV I/O가 실제 TP/SL 감지보다 먼저 실행된다. 연구 episode와 저장량이 늘면 실제 청산 감지가 늦어질 수 있다.

### 6-2. v1.7.0 필수 순서

```text
1. 실시간 가격·시각 캐시 갱신
2. 실제 보유 포지션 청산조건 판단
3. 실제 trigger 상태를 원자적으로 고정
4. 실제 청산 worker 제출
5. 이후 paper/counterfactual/path 연구 처리
6. 연구 결과는 전용 queue에 전달
7. 전용 writer가 batch 저장
```

핵심 invariant:

> 연구 계산 또는 연구 CSV 저장이 느리거나 실패해도 실제 TP/SL 감지와 청산 worker 제출을 지연·중단시키지 않는다.

### 6-3. executor와 queue 격리

- 실주문 executor와 연구 writer/executor를 공유하지 않는다.
- broker precheck 내부 병렬조회 pool도 연구 pool과 공유하지 않는다.
- 연구 queue는 bounded queue로 만든다.
- 실제 주문, `live_state`, `live_orders`, `live_trades`는 연구 queue로 보내지 않는다.
- shutdown 시 신규 주문 차단 후 연구 queue를 제한시간 내 flush한다.
- flush 실패·잔여행 수를 로그로 남긴다.

연구 데이터 우선순위:

```text
P0: 실제 주문·체결·live_state — 연구 queue와 완전 분리, 기존 안전정책 유지
P1: 169-grid 최종결과·counterfactual 최종요약 — 보존 우선
P2: 상세 경로 snapshot — 부하 시 해상도 축소 가능
```

- P2 축소가 발생하면 조용히 버리지 않고 누락 건수·구간·이유를 기록하고 Telegram 경고한다.
- P1을 임의로 drop하지 않는다.
- 연구 writer 오류를 실제 주문 SAFE HALT로 자동 승격하지 않는다.
- 다만 연구 실패를 숨기지 말고 명확히 알린다.

### 6-4. batch CSV 저장

현재처럼 한 행마다 작은 DataFrame을 생성해 `to_csv(mode="a")`하지 않는다.

- 예: 1초 또는 50~200행 단위 batch
- 파일별 단일 writer
- header 중복 방지
- UTF-8 BOM 및 기존 CSV 호환성 유지
- queue length, oldest age, batch rows, write duration, failure count 기록
- 프로그램 정상종료·사용자 중단·새 거래일 전환 시 안전 flush

구체적 batch 크기는 설정값으로 두고 부하테스트로 확정한다. 숨은 하드코딩으로 두지 않는다.

## 7. broker precheck 병렬화 — 실제 적용 확정

사용자 최종 결정: **v1.7.0 실제 청산 경로에 적용한다.**

목표는 안전검사 제거가 아니라 독립 조회를 병렬화해 trigger→order 지연을 줄이는 것이다.

과거 실측:

```text
2026-09-01 비에이치 trigger→fill 약 12.57초
2026-09-04 broker precheck 5.43~12.30초
2026-09-04 trigger→order 7.70~14.80초
```

필수 보존:

- broker 실제 보유수량
- 매도가능수량
- 미체결 주문
- KRX/NXT 등 거래소별 조회 의미
- 자동관리수량 / 외부수량 분리
- 진행 중 동일 종목 SELL 중복 차단
- `ORDER_STATUS_UNKNOWN` SAFE HALT
- `EXIT_ERROR`
- 부분 성공을 정상 잔고로 간주하지 않는 원칙
- stale cache만으로 매도하지 않는 원칙

구현 원칙:

1. 실제로 독립인 조회만 bounded 병렬 실행한다.
2. API rate limit과 broker 제한을 존중한다.
3. 각 조회의 start/end/duration/success/error/retry를 별도 기록한다.
4. 전체 precheck start/end/duration도 유지한다.
5. 하나라도 필수조회가 실패하면 기존 안전 실패정책을 유지한다.
6. 병렬화 때문에 일부 결과가 다른 청산 건과 섞이지 않도록 request/position 식별자를 유지한다.
7. worker timeout·cancel·shutdown 동작을 정의하고 회귀검증한다.

비교 지표:

```text
trigger→live-check-complete
trigger→precheck-start
각 독립 precheck duration
전체 precheck duration
trigger→order
order→fill
trigger→fill
trigger price 대비 fill slippage
```

## 11. 새로운 진입전략 — Shadow 전용

목표는 75점 임계값을 70점이나 80점으로 미세조정하는 것이 아니다.

> 상승 중후반의 FIRST_75_PASS보다 앞선 상승 초중반 구조를 독립 패턴으로 포착한다.

기존 FIRST_75_PASS는 실전 기준선으로 유지한다. 새 전략은 충분한 날짜 밖 검증 전까지 어떤 경우에도 실제 주문 함수에 전달하지 않는다.

### 11-1. 연구군

```text
NEW_EARLY_ACCEL_SHADOW
NEW_FIRST_PULLBACK_SHADOW
NEW_WATCH_RECLAIM_SHADOW
```

연구 의미:

1. **Early Acceleration**
   - high_gap이 아직 과도하지 않은 구간
   - 15/30/60초 가격이 최초 동시 양전환 또는 가속
   - 거래량·거래대금 증가 동반
   - 120~300초 추세가 이미 과열된 경우 구분

2. **First Pullback Continuation**
   - 초기 상승 뒤 첫 얕은 눌림
   - 단기 30초 약화와 120/300초 추세 유지
   - 고점이격 축소 뒤 재상승/회복
   - 건강한 눌림과 급락전환을 별도 feature로 기록

3. **Watch Reclaim**
   - WATCH episode 선행
   - 가격·거래대금 압축
   - 단기 고점 또는 기준가격을 거래활성도와 함께 재돌파

### 11-2. 과잉확정 금지

기존 데이터의 단순 exploratory 조건은 비용 후 음수였다.

```text
Early Acceleration 단순조건: 전체 net 평균 약 -0.238%
First Pullback 단순조건: 전체 net 평균 약 -1.078%
Steady Acceleration 단순조건: 전체 net 평균 약 -0.155%
2026-09-03~04 짧은 holdout에서도 모두 net 음수
```

따라서 위 단순 임계값을 “검증된 새 전략”으로 구현하면 안 된다.

v1.7.0에서는:

- 연구 event를 넓되 명시적인 configurable provisional rule로 기록한다.
- rule version과 threshold를 모든 결과행에 남긴다.
- 동일 종목·동일 mode·동일 WATCH episode 중복진입을 막는다.
- episode/cooldown 상한을 둔다.
- live gate와 코드 경로를 구조적으로 분리한다.
- exact threshold는 향후 데이터 분석 대상이며 실전 조건이 아니다.

임계값 선택이 부모 데이터 구조로 명확히 구현되지 않으면 추정하지 말고, 넓은 관찰 이벤트와 feature snapshot 수집을 우선한다.

### 11-3. entry-time feature

진입 당시 알 수 있는 값만 저장한다.

- 15/30/60/120/180/300초 가격변화와 실제 관측간격
- 30/60/120/180/300초 high_gap 변화
- current change rate / high_gap
- 거래량·거래대금·증가율·순위
- watch 시작값·지속시간·episode id
- prior shadow 여부와 시간·가격차
- score와 구성항목은 설명용으로 기록
- scanner 시장상태 proxy

진입 후 MFE/MAE/exit 결과를 진입 feature로 사용하지 않는다.

- 투자금액·횟수·총예산 강제 고정
- broker 실패 시 매도를 계속할지 안전검증 없이 정책 변경
- queue overflow에서 P1 데이터를 조용히 폐기
- API 병렬 호출 수를 rate-limit 검증 없이 확대
- 기존 CSV 컬럼 삭제·개명
- 기존 Shadow mode 축소·삭제

구현 중 부모 구조 때문에 중요한 선택이 새로 필요하면 임의 결정하지 말고 사용자에게 보고한다.

## 21. 최종 인수인계 요약

> v1.7.0의 실제 매매는 FIRST_75_PASS, 09:05~09:30, T250/S150, 동일 종목 하루 1회, 15:20 강제청산을 유지한다. 수익보호와 Noon Recovery는 실제 주문에서 제거하고 Shadow 데이터만 수집한다.

> 새 조기진입 조건, 수익보호 16개 조합, Noon/오후 회복청산은 연구 전용이다. 충분한 날짜 밖 검증 전 실제 주문에 연결하지 않는다.

> broker precheck는 안전조회 전체를 유지한 채 독립 조회만 병렬화한다. 부분 성공, stale cache, 중복 SELL을 정상으로 처리하지 않는다.

> 실시간 틱에서는 실제 포지션 판단과 worker 제출이 paper 계산·연구 CSV 저장보다 반드시 먼저다. 연구 저장은 별도 bounded queue와 batch writer로 격리한다.

> 부모 v1.6.10을 직접 보존하고 확정 변경만 국소 통합한다. 4개 셀, 주문 안전장치, 기존 연구체계, 169-grid, QUICK REFERENCE와 CONTINUITY를 흔들지 않는다.

이 다섯 문장이 v1.7.0 구현의 최상위 기준이다.

## 22. 2026-09-07 (월) 실행 전 재감사 최종 결정

사용자 최종 결정:

- v1.7.0은 아직 실행 전이므로 동일 release 파일을 수정본으로 교체한다.
- 신규 조기진입 Shadow는 성과 최적화된 숨은 numeric cutoff를 두지 않고 넓은 방향성 관찰 이벤트로 수집한다.

- Noon/오후 회복청산 최소 6개 정책명 적용

## 23. README / 인수인계서 충돌 처리 프로세스

앞으로 전체 코드 작성 시 `README.md`, 해당 작업의 최신 최종 인수인계서, 사용자가 지정한 직전 검증 release 전체를 모두 읽는다.

우선순위와 중단 기준:

1. 최신 인수인계서에 명확한 최신 사용자 결정이 있으면 이전 일반값을 덮을 수 있다.
2. README는 부모 보존·주문 안전·데이터 무결성·전달 방식 등 장기 불변 원칙을 담당한다.
3. 두 문서가 안전·실주문·데이터 보존 문제에서 상반되거나 해석이 불분명하면 어느 한쪽을 임의 선택하지 않는다.
4. 그런 충돌은 전체 코드 작성 전에 사용자에게 보고하고 확인될 때까지 구현을 중단한다.
5. 확인된 결정은 코드 CONTINUITY와 최신 인수인계서에 기록하고, 장기 기준이 바뀌었다면 README도 같은 작업에서 갱신한다.
6. 불분명한 내용은 실제 주문에 연결하지 않고 Shadow 또는 미구현으로 둔다.

v1.7.0 비용 충돌은 명확한 최신 결정으로 해결한다.

```text

v1.7.0 이후 신규 연구·보고: 0.24%
```
