## 3. 후보 등록과 관찰 생명주기

### 3.1 후보

아래 신호 중 하나라도 당일 발생하면 눌림 후보로 등록한다.

- BASE
- FIRST_75_PASS

동일 종목 후보는 당일 하나이며 `candidate_source`는 `BASE`, `FIRST_75_PASS`, `BOTH` 중 하나다. 부모 trade/event id를 모두 연결한다.

### 3.2 지속관찰

- BASE/FIRST_75 paper grid가 모두 종료돼도 후보는 관찰 종료까지 유지한다.
- 반복 REST 조회를 추가하지 않고 기존 WebSocket과 완료 1분봉 집계를 재사용한다.
- paper position과 candidate watcher의 구독 생명주기를 분리한다.
- 후보 또는 열린 paper position 중 하나라도 필요하면 구독을 유지한다.
- 같은 종목 중복 subscribe 금지.

### 3.3 완료봉만 판정

- 전략 상태 전환은 완료된 1분 OHLCV 봉만 사용한다.
- 미완성 현재봉·후행 수정봉으로 과거 신호를 다시 만들지 않는다.
- 후보 등록 중간봉, 재시작 첫 봉, WS sequence gap, 재연결 불완전봉은 확정 판단에서 제외한다.
- `DATA_UNAVAILABLE`, `RECOVERY_PARTIAL` 의미를 보존한다.

## 4. 공통 가격 정의

| 기호 | 정의 |
|---|---|
| `H` | 후보 등록 이후, 아직 유효 눌림 episode가 시작되기 전까지의 완료봉 최고가 |
| `L1` | `H` 대비 눌림 시작 후 형성된 첫 유효 지지후보 저점 |
| `R1` | `L1` 이후 +0.40% 이상 회복이 확인된 뒤 L2 retest가 시작되기 전까지의 완료봉 최고가 |
| `B` | 고정 돌파선. `R1` 확정 시 그 가격으로 고정 |
| `L2` | `R1/B` 이후 재눌림 과정의 저점. L1 방어 또는 Higher Low 확인용 |
| `close` | 해당 완료 1분봉의 마지막 체결가격. 일봉 종가가 아님 |

가격은 float 산술값을 그대로 주문/신호가격으로 사용하지 않는다. `B × 1.001` 등 계산 후 기존 유효 호가단위 helper로 올림하여 실제 비교가격을 만든다. 새 호가표를 별도 하드코딩하지 않는다.

## 6. episode 상태머신

```text
CANDIDATE
  ↓
PEAK_TRACKING(H)
  ↓ H 대비 -1.50%
L1_TRACKING
  ↓ L1 대비 종가 +0.40%
R1_TRACKING
  ↓ R1 대비 종가 -0.30%
L2_TRACKING
  ├─ L1 -0.30% 종가 이탈 → RESET_NEW_LOW
  └─ L2 대비 종가 +0.40% → STRUCTURE_READY(B 고정)
                                      ↓
                               B+0.10% 종가 돌파
                                      ↓
                               다음 완료봉 유지
                                      ↓
                         PULLBACK_STRUCTURE_ENTRY
```

### 6.1 눌림 시작

완료봉 저가가 아래를 충족하면 눌림 관찰을 시작한다.

```text
bar_low <= H × (1 - 0.015)
```

같은 봉 안의 high/low 선후는 알 수 없으므로 H 신규고점 봉과 같은 봉에서 눌림을 확정하지 않는다. 다음 완료봉부터 평가한다.

### 6.2 L1

- 눌림 시작 뒤 완료봉 저가의 running minimum을 L1 후보로 둔다.
- 새로운 저가가 나오면 L1 후보가격과 시간을 갱신하고 아직 생성되지 않은 snapshot schedule을 다시 계산한다.
- L1 기준 snapshot clock은 현재 유효 L1의 완료봉 시각에서 시작한다.

### 6.3 R1과 B

완료봉 종가가 아래를 처음 충족하면 의미 있는 반등이 시작된 것으로 본다.

```text
close >= L1 × 1.004
```

이후 완료봉 high의 running maximum을 R1으로 추적한다. 완료봉 종가가 R1에서 0.30% 이상 다시 눌리면 retest 시작으로 보고 직전 R1을 B로 고정한다.

```text
close <= R1 × 0.997
B = R1
```

B는 같은 유효 episode 안에서 낮추지 않는다. 최근 5분 고점으로 교체하지 않는다.

### 6.4 L2와 구조완성

- retest 시작 뒤 완료봉 저가의 running minimum을 L2로 둔다.
- 완료봉 종가가 `L1 × 0.997` 미만이면 기존 바닥가설을 폐기한다.
- 이 경우 B를 낮추지 말고 새 저점을 L1으로 하는 새 episode로 reset한다.
- L2 이후 완료봉 종가가 `L2 × 1.004` 이상이면 L2 방어가 확인되어 `STRUCTURE_READY`가 된다.
- `L2 > L1`이면 `higher_low=True`; 동일권 방어도 허용한다.

### 6.5 고정 돌파선 B와 종가 돌파

```text
raw_threshold = B × 1.001
reclaim_threshold_price = ceil_to_valid_tick(raw_threshold)
```

현재가가 장중 threshold를 순간 통과한 것만으로 신호를 만들지 않는다.

```text
completed_bar_close >= reclaim_threshold_price
```

일 때 `BREAKOUT_CLOSE_CONFIRMED`로 전이한다.

### 6.6 다음 1분봉 유지/retest

돌파 다음 완료봉 종가가 아래를 충족해야 한다.

```text
next_close >= B × (1 - 0.002)
```

장중 저가가 B 아래로 내려갔더라도 완료봉 종가가 허용범위 안에서 회복하면 retest 방어로 인정한다. 다음 봉 종가가 허용범위 아래면 해당 돌파는 실패로 기록하고 B를 유지한 채 다음 종가 돌파를 기다린다.

2·3·5개 완료봉 또는 3·5분 추가유지는 **다음 연구 후보**다. v2.3.0 필수조건으로 추가하지 않는다.

## 7. PULLBACK_STRUCTURE_ENTRY

### 7.1 진입

다음을 모두 충족하면 신호를 만든다.

- 유효 `L1 → R1/B → L2` 구조 완성
- L1 종가 이탈 없음
- B+0.10% 완료봉 종가 돌파
- 다음 완료봉이 B−0.20% 이상에서 유지
- 현재시각 `< 15:10`
- 동일 종목·동일 날짜 STRUCTURE 미진입

신호 확정 뒤 첫 수신 정상 tick을 fill로 사용한다. 신호시각/가격과 fill시각/가격을 분리 저장한다.

### 7.2 시간

- 최소 형성시간 없음
- 최대 형성시간 없음
- 단, 당일 `15:20`까지만 평가하고 신규 진입은 `15:10` 이전만 허용
- 구조형성시간은 필터가 아니라 `structure_elapsed_min` feature로 저장

### 7.3 중복

- 동일 종목·동일 날짜 최대 1회
- 새 episode가 생겨도 이미 STRUCTURE 진입했다면 추가 STRUCTURE 진입 금지

## 8. SNAPSHOT 공통 규칙

### 8.1 horizon

```text
30, 60, 90, 120, 150, 180, 210, 240분
```

총 8개다. 20분 간격·360분 설계는 폐기한다.

```text
snapshot_time = valid_L1_time + horizon_min
```

L1이 종가 기준으로 무효화되면 기존 episode의 아직 도달하지 않은 schedule을 취소하고 새 L1에서 다시 계산한다. 이미 기록한 과거 snapshot row는 삭제하지 않고 episode id와 `INVALIDATED_LATER` 여부로 연결한다.

### 8.2 세션 종료

- snapshot 평가시간이 `15:20` 이후면 `NOT_REACHED_SESSION_END`
- 15:10 이상 15:20 미만에 READY/RECLAIM이어도 신규 진입하지 않고 `ENTRY_TIME_CLOSED` 저장
- 미래 봉을 당겨서 평가하지 않는다.

### 8.3 support touch 계산

지지권은 아래로 정의한다.

```text
support_touch_upper = L1 × 1.003
support_break_lower = L1 × 0.997
```

- 완료봉 low가 `support_touch_upper` 이하이고 종가가 `support_break_lower` 이상이면 touch 후보
- 연속 인접봉을 여러 번 세지 않는다.
- 한 touch 뒤 종가가 L1 대비 +0.40% 이상 이격된 뒤 다시 돌아온 경우에만 새 touch로 센다.
- 최초 L1을 첫 touch로 포함한다.

### 8.4 SNAPSHOT READY/WATCH/REJECT

각 horizon의 완료시점까지 관측된 데이터만 사용한다.

필수 READY 조건:

1. 완료봉 종가가 L1−0.30% 아래로 이탈한 적 없음
2. `support_touch_count >= 2`
3. 현재 종가가 관찰구간 중간가격 이상
4. 최근 확인된 swing high와 swing low가 모두 낮아지는 명확한 하락구조가 아님

구간 위치:

```text
base_low = min(low since valid L1)
base_high = max(high since valid L1)
base_mid = (base_low + base_high) / 2
close_position = (close - base_low) / (base_high - base_low)
```

`base_high == base_low`면 위치값은 결측으로 두고 READY가 아니라 WATCH다.

판정:

- 필수조건 모두 충족: `READY`
- L1은 유효하지만 일부 부족: `WATCH`
- L1 종가이탈 또는 데이터 불완전으로 판단불가: 각각 `REJECT_RESET`, `DATA_UNAVAILABLE`

`base_range_pct <= 1.20%`, `reclaim_volume_ratio >= 1.50`은 v2.3.0 필수 READY 조건이 아니다. feature로 저장해 누적 후 결정한다.

### 8.5 하락구조 판정

- 완료봉 기반으로 확인된 최근 두 swing high와 최근 두 swing low가 모두 이전 값보다 낮으면 `descending_structure=True`.
- swing 표본이 부족하면 False로 단정하지 말고 `UNKNOWN`으로 저장하며 READY는 WATCH로 낮춘다.
- 현재봉 자기참조와 미래봉 pivot 확정 금지.

## 9. PULLBACK_SNAPSHOT_DIRECT

각 horizon의 snapshot 완료봉에서 `READY`이면 DIRECT 신호를 만든다.

- 신호가격: snapshot 완료봉 close
- fill: 신호 뒤 첫 수신 정상 tick
- B 돌파 필수 아님
- 현재시각 `< 15:10`
- 동일 종목·동일 날짜·동일 horizon·DIRECT 최대 1회
- 다른 horizon의 DIRECT는 독립 진입 허용
- 같은 종목 최대 8회 가능

`WATCH`, `REJECT_RESET`, `DATA_UNAVAILABLE`, `ENTRY_TIME_CLOSED`는 평가 row만 저장하고 paper grid와 Telegram을 만들지 않는다.

## 10. PULLBACK_SNAPSHOT_RECLAIM

각 horizon에서 READY가 된 뒤 해당 horizon 전용 reclaim 대기를 시작한다.

### 10.1 B

- 해당 snapshot 시점까지 유효한 확정 R1이 있으면 그 R1을 B로 사용한다.
- R1/B가 아직 없으면 `WAIT_NO_FIXED_B`로 저장하고 B가 확정된 뒤 reclaim을 기다린다.
- B를 최근 5분 고점으로 대체하지 않는다.

### 10.2 진입

- READY snapshot 존재
- B+0.10% 완료봉 종가 돌파
- 다음 완료봉 종가가 B−0.20% 이상 유지
- 현재시각 `< 15:10`
- 동일 종목·동일 날짜·동일 horizon·RECLAIM 미진입

각 horizon은 독립 비교군이다. 하나의 실제 돌파가 여러 READY horizon 조건을 동시에 만족하면 horizon별 독립 trade를 같은 `shared_entry_group_id`로 생성할 수 있다. 동일 가격·시간을 공유하더라도 trade_id와 `snapshot_horizon_min`은 분리한다.

같은 종목 최대 8회 가능하다.

## 14. Telegram

README의 `Telegram 메시지 가독성 규칙`을 필수 적용한다.

### 14.1 발송 대상

- BASE 실제 가상진입
- FIRST_75_PASS 실제 가상진입
- PULLBACK_STRUCTURE_ENTRY 실제 가상진입
- PULLBACK_SNAPSHOT_DIRECT 실제 가상진입
- PULLBACK_SNAPSHOT_RECLAIM 실제 가상진입

SNAPSHOT `READY/WATCH/REJECT` 평가만으로는 발송하지 않는다.

### 14.2 형식

- 종목명 다음 줄에 종목코드 단독 표시
- 시간·가격·차트판정·전략을 문단별로 그룹화
- 문단 사이만 빈 줄
- 문단 내부 세부항목은 `-` 글머리기호
- 모든 줄 사이에 빈 줄을 넣지 않음
- 마지막에 `연구용 가상진입`, `실제주문 없음`
- SNAPSHOT 제목에 horizon과 DIRECT/RECLAIM 명시

예:

```text
🟨 SNAPSHOT 90분 RECLAIM 가상진입

하나마이크론
종목코드 : 067310

⏱ 스냅숏
- 첫 저점 : 10:32
- 90분 평가 : 12:02
- 돌파 확인 : 12:16
- 체결 : 12:17

📊 차트판정
- 평가 : READY
- 고정 돌파선 B : 44,400원
- 돌파기준가 : 44,450원
- 돌파종가 : 44,500원

💰 체결가
- 44,500원

진입판정
90분 READY + 고정 상단 RECLAIM

연구용 가상진입
실제주문 없음
```

값은 runtime snapshot에서 동적으로 만들며 예시 문자열을 하드코딩하지 않는다.

### 14.3 outbox

## 15. 재시작과 원자성

state JSON에 최소 다음을 복구한다.

- 후보와 source
- 현재 episode id/state
- H/L1/R1/B/L2와 시각
- scheduled/completed snapshot horizons
- horizon별 READY/WATCH/REJECT와 pending reclaim
- 당일 STRUCTURE 진입 여부
- horizon/mode별 SNAPSHOT 진입 여부
- 열린 reference trade와 63-grid
- signal/fill ledger dedup key
- Telegram outbox

원자성:

1. signal event 예약
2. 다음 정상 tick fill 원자확정
3. reference trade + 63-grid 전체 생성
4. CSV/state checkpoint
5. Telegram outbox 발송

중간 crash에서 일부 grid만 생기거나 Telegram만 발송되는 상태를 금지한다. FILL ledger를 기준으로 복구한다.

관찰하지 못한 재시작 구간의 1분봉을 추정해 구조나 snapshot을 만들지 않는다.
