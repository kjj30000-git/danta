# 7. v1.6.7에서 이미 해결된 주문엔진 안전사항 — 반드시 보존

## 7-1. BUY/SELL 부분체결 누적수량 계산

금지:

```python
order["filled_qty"] += values["911"]
```

기본 원칙:

```text
requested_qty = 프로그램 주문수량
unfilled_qty = broker 미체결수량

broker_filled_qty = requested_qty - unfilled_qty
delta_qty = broker_filled_qty - prev_filled_qty
```

포지션에는 `delta_qty`만 반영.

항상:

```text
0 <= broker_filled_qty <= requested_qty
```

보장.

---

## 7-2. 종목 격리 vs 시스템 SAFE HALT

특정 종목 오류:

```text
MANUAL_INTERVENTION_REQUIRED
POSITION_MISMATCH
EXIT_ERROR
EXTERNAL_ORDER_DETECTED
```

→ 해당 종목 추가 자동주문 차단 / 당일 실제 재진입 금지  
→ 다른 종목 실매매는 계속.

시스템 전체 주문상태를 신뢰하기 어려운 경우:

```text
ORDER_STATUS_UNKNOWN
여러 종목 동시 심각한 상태불일치
주문/체결 스트림 자체 신뢰불가
사용자 전체중단
```

→ 실제매매 전체 SAFE HALT  
→ 가상매매/연구/데이터수집 계속.

---

## 7-3. 실제 매도수량

```text
가격판단 = WebSocket 전략기준
수량판단 = broker 실제계좌 상태
```

내부수량과 broker수량이 달라도 broker의 `held_qty / sellable_qty`를 정상 확인할 수 있으면
**broker 실제 매도가능수량 기준으로 안전하게 청산**한다.

broker 수량 자체를 신뢰할 수 없으면 임의수량 매도 금지.

---

## 7-4. TP/SL 기준가격

TP/SL은 **프로그램 실제 평균체결가(WebSocket 체결 기반)**로 설정.

이후 broker 계좌 평균매입가가 달라도 TP/SL 목표가격을 다시 계산하지 않는다.

---

## 7-5. broker 계좌조회

TP/SL 가격감시는 WebSocket으로 빠르게 유지.

broker 조회는 계좌상태/수량 검증을 위한 안전검증 흐름으로 사용.

구분:

```text
broker_held_qty
broker_sellable_qty
pending_auto_buy_qty
pending_auto_sell_qty
auto_managed_qty
external_qty
```

---

## 7-6. 기존 보유종목

프로그램 시작 시 이미 계좌에 있던 장기/기존 보유종목:

```text
가상연구 O
실제 자동매수 X
실제 5종목 카운트 X
```

실제매수 직전에도 broker 잔고 재확인.

## 7-7. 수동 추가매수

예:

```text

사용자 수동추가 20주
broker 총보유 120주
```

→ `auto_managed_qty=100`, `external_qty=20`

자동 TP/SL에서는 자동관리 100주만 매도.

## 7-8. 수동매도

외부 SELL 발생 시 `EXTERNAL_ORDER_DETECTED`.

전량 수동매도:

```text
broker held_qty = 0
→ EXTERNAL_EXIT_CONFIRMED
→ 자동포지션 종료
→ TP/SL 관리 종료
→ 당일 실제 재진입 금지
```

부분 수동매도:

```text
external_qty 먼저 차감
그 다음 auto_managed_qty 차감
```

예:

```text
auto=100
external=20
사용자 수동매도=50
→ external=0
→ auto=70
```

---

## 7-9. 자동매도 중 사용자 수동개입

기존 자동매도 주문을 프로그램이 자동취소하지 않는다.

```text
외부매도 감지
→ 해당 종목 추가 자동주문 차단
→ 기존 자동주문 체결상태 확인
→ broker 잔고 확인
→ 잔여 자동관리수량 동기화
```

자동 주문취소 기능은 아직 넣지 않는다.

종료 요청 즉시:

→ 모든 신규 BUY/SELL submit 금지

# 11. 수동매도 손익 반영 상세 요구사항

## 11-1. 다른 종목 개인매매는 무시

사용자가 프로그램과 무관한 다른 종목을 직접 사고파는 경우:

```text
자동포지션 편입 X
자동 TP/SL X
live_trade_count 영향 X
live_daily_realized_pnl 영향 X
```

프로그램 자동관리 종목과 관련된 외부 SELL만 처리.

---

## 11-2. 외부 주문도 누적체결량 기반 delta 계산

외부 SELL WebSocket 주문체결 이벤트도
주문번호 기준 ledger를 관리.

기본:

```text
external_requested_qty = broker 주문수량
external_unfilled_qty = broker 미체결수량

external_broker_filled_qty
    = external_requested_qty - external_unfilled_qty

external_delta_qty
    = external_broker_filled_qty - prev_external_filled_qty
```

`911` 체결량을 이벤트마다 단순 누적하지 않는다.

동일 누적체결 이벤트 재수신 시 수량 증가 금지.

---

## 11-3. 외부 SELL 수량 배분

수동매도 delta 발생 시:

```text
1. external_qty에서 먼저 차감
2. 남는 수량만 auto_managed_qty에서 차감
```

예:

```text
auto=100
external=20
수동매도 delta=50

external에서 20 차감
자동관리에서 30 차감

결과:
external=0
auto=70
```

실현손익 계산 대상은 **자동관리에서 실제로 감소한 30주만**.

---

## 11-4. 수동매도 손익 계산

자동관리 물량에서 감소한 수량:

```text
external_auto_exit_qty
```

에 대해:

```text
실제 외부매도 체결가
vs
해당 자동포지션 실제 평균매입가
```

로 비용 전 손익 계산.

자동매도와 동일한 gross 기준 사용.

최소 기록:

```text
stock_code
stock_name
entry_price
external_exit_price
external_auto_exit_qty
return_rate_gross
pnl_gross_won
result = EXTERNAL_EXIT / EXTERNAL_PARTIAL_EXIT 등
external_order_no
external_fill_time
```

그리고:

```text
live_daily_realized_pnl += 자동관리 물량의 외부청산 실현손익
```

반드시 반영.

하루 손실한도(`LIVE_DAILY_MAX_LOSS_WON`)에도 포함.

---

## 11-5. 전량 수동매도

자동관리 잔량이 수동매도로 전부 사라지면:

```text
EXTERNAL_EXIT_CONFIRMED
자동포지션 종료
TP/SL 종료
당일 실제 재진입 금지
live_trades에 실현손익 기록
live_daily_realized_pnl 갱신
```

---

## 11-6. 부분 수동매도

예:

```text
auto 100
external 20
수동 SELL 50
```

→ 자동관리 30주에 대한 실현손익만 기록  
→ auto 70주는 기존 TP/SL 관리 계속.

부분 수동매도 때문에 포지션 전체를 종료하지 않는다.

## 11-7. 자동매도 주문 진행 중 수동개입

기존 정책 유지:

```text

추가 자동주문 차단
기존 자동주문 체결상태 확인
broker 잔고 동기화
```

수동매도와 자동매도가 섞여 같은 수량을 두 번 손익 반영하지 않도록
주문번호/체결 delta 기준으로 분리.
