## 0. 이번 대화에서 확정된 핵심

이번 검토에서 사용자가 의도한 STRUCTURE/SNAPSHOT 패턴을 다음처럼 명확히 정의했다.

> **장초반 큰 움직임 이후, 충분한 시간 동안 저변동 + 보합 상태를 유지한 종목을 찾고, 그 이후 움직임을 연구한다.**

중요한 점:

- 단순히 `L1이 깨지지 않았다`거나 `하락구조가 아니다`만으로 충분하지 않다.
- **우상향도, 우하향도, 큰 폭의 상하 진동도 사용자가 원한 패턴과 다르다.**
- 사용자가 원하는 것은 **방향성이 작고 변동성이 낮은 안정된 횡보/보합 상태**다.
- 이 전략은 FIRST_75_PASS의 장초반 급등 추격형과 별개의 전략으로 판단한다.
- STRUCTURE/SNAPSHOT 분석에서 FIRST_75 점수 논리를 섞지 않는다.

## 1. SNAPSHOT 시간축: 삭제 금지, 전부 유지

현재 SNAPSHOT horizon:

```text
30, 60, 90, 120, 150, 180, 210, 240분
```

이번 대화 중 90분 이상이 사람 눈에 더 자연스러워 보인다는 인상이 있었지만, **90분은 아직 가설일 뿐 확정 기준이 아니다.**

따라서 다음 버전에서도:

- 30/60분 삭제 금지
- 90분 최소시간 하드코딩 금지
- 120/150/180/210/240분 축소 금지
- 모든 기존 horizon을 동일하게 계속 수집
- 어느 horizon이 가장 적합한지는 누적 데이터로 판단

사용자 표현을 그대로 반영하면:

> 90분일 수도 있지만 70분일 수도 있고 200분일 수도 있다. 시간은 데이터를 보고 판단한다.

즉 다음 버전에서는 시간 cutoff를 추가하는 것이 아니라 **각 horizon의 “저변동+보합 정도”를 더 잘 수치화하여 저장하는 것**이 핵심이다.

## 2. 현재 SNAPSHOT 로직의 한계

v2.3.1은 v2.3.0의 SNAPSHOT 전략조건을 유지한다.

현재 READY 핵심 조건:

1. L1 종가 이탈 없음
2. `support_touch_count >= 2`
3. 현재 종가가 관찰구간 중간 이상
4. 최근 swing high와 swing low가 모두 낮아지는 명확한 하락구조가 아님

현재 이미 저장하는 관련 feature:

- `base_range_pct`
- `close_position_in_base`
- `range_compression_ratio`
- `descending_structure`
- `support_touch_count`
- `higher_low_count`
- `distance_to_b_pct`
- `volume_contraction_ratio`
- `reclaim_volume_ratio`

하지만 현재 설계상 `base_range_pct <= 1.20%`는 READY 필수조건이 아니며 feature로만 저장한다.

### 2.1 이번 데이터에서 확인된 문제

- 코리아써키트

반면 사용자가 의도에 더 가깝다고 본 사례:

## 3. 다음 버전에서 추가/보완할 “저변동 + 보합” feature

### 3.1 원칙

**바로 진입 필터로 하드코딩하지 않는다.**

먼저 feature를 저장하고, 사람 눈과 데이터가 일치하는지 누적 검증한다.

### 3.2 저변동성 측정

기존 `base_range_pct`는 유지한다.

추가 후보:

- 최근 N분 또는 해당 snapshot 전체의 high-low range %
- rolling range 평균/중앙값
- ATR 유사값 또는 평균 true range %
- 봉별 절대 수익률 평균
- 봉별 절대 수익률 중앙값
- 큰 1분봉 비중
- 전체 구간 중 상·하단 터치 횟수

목표:

- 단순 시작가와 끝가가 비슷한 V/W형 고변동 구간을 “보합”으로 오인하지 않게 한다.

### 3.3 보합/방향성 측정

현재 `descending_structure`만으로는 부족하다.

추가 후보:

- snapshot 시작 가격 대비 종료 가격 변화율
- 가격 vs 시간 선형회귀 slope
- slope를 가격으로 정규화한 `trend_slope_pct_per_min`
- 전반부 평균/중앙 가격 vs 후반부 평균/중앙 가격 차이
- 최근 고점들의 기울기
- 최근 저점들의 기울기
- 중심가격 이동량
- 순변화량 / 총 이동량 비율 (efficiency ratio 유사)
- 방향성 score의 절대값

목표 분류:

```text
저변동 + 보합
저변동 + 우상향
저변동 + 우하향
고변동 + 보합
고변동 + 방향성
```

사용자가 원하는 1차 목표는 **저변동 + 보합**이다.

### 3.4 중요한 금지사항

- “우상향이면 좋은 것”으로 처리하지 않는다.
- “우하향만 아니면 READY”라는 기존 단순 기준에 의존하지 않는다.
- range 하나만 보고 저변동으로 단정하지 않는다.
- 시작가와 종료가가 비슷하다는 이유만으로 보합으로 단정하지 않는다.
- 미래 봉을 사용해 과거 snapshot을 재분류하지 않는다.

## 4. 오늘 차트 검토 방식: 다음 데이터 분석의 표준 추가사항

앞으로 STRUCTURE/SNAPSHOT 리뷰에서는 **각 신호/평가 시점의 차트를 같이 본다.**

각 종목마다 가능한 경우:

- 30분
- 60분
- 90분
- 120분
- 150분
- 180분
- 210분
- 240분

전부 비교한다.

차트에는 최소 다음을 표시한다.

- 후보 등록
- L1
- R1 / B
- L2
- snapshot 평가 시점
- DIRECT / RECLAIM 신호
- 실제 가상 fill
- 청산

분석 목적:

1. 코드의 READY와 사람 눈의 “저변동+보합”이 일치하는지
2. 짧은 horizon에서만 잘못 READY가 발생하는지
3. 긴 horizon에서도 방향성 종목이 READY로 남는지
4. 어떤 feature가 사람 판단과 가장 잘 구분되는지
5. 적절한 horizon이 자연스럽게 어디에서 나타나는지

## 7. TP/청산 연구: 고정 수익률 외 “당일 고점 연동” 추가 검토

사용자 아이디어:

> 이 전략은 수익률을 정할 때 당일 고점에서 일정 비율 아래 수준으로 정하는 것이 더 자연스러울 수 있다.
> 고정 +2% 목표가가 당일 고가를 넘어서는 경우 달성하기 어려울 수 있다.
> 장초반 급등형보다 수익폭은 낮고, 대신 승률이 높을 가능성이 있다.

이것은 아직 가설이며 즉시 실제 청산 규칙으로 적용하지 않는다.

### 7.1 다음 분석에서 비교할 목표가

고정 TP:

```text
+1.00%
+1.25%
+1.50%
+1.75%
+2.00%
+2.25%
+2.50%
+2.75%
+3.00%
```

당일고점 연동 후보:

```text
진입 시점까지의 당일 고점 × 0.990
진입 시점까지의 당일 고점 × 0.995
진입 시점까지의 당일 고점 × 1.000
필요 시 당일 고점 + 소폭 돌파 수준
```

### 7.2 반드시 구분할 고점

- `H`: pullback episode 내부 고점
- `base_high`: snapshot 관찰구간 고점
- **진입 시점까지의 실제 당일 고점**

이 셋을 혼동하지 않는다.

TP 연구의 기본 reference는 우선 **진입 시점까지의 실제 당일 고점**을 별도 계산하여 사용한다.

### 7.3 분석 항목

각 trade마다:

- entry_price
- 진입 시점까지의 day_high
- `(day_high / entry_price - 1)`
- 고정 +2% 목표가가 day_high 위/아래인지
- 진입 후 MFE
- day_high -1.0%, -0.5%, 0% 목표 도달 여부
- 목표 도달 전 MAE
- 목표 도달 시간
- SNAPSHOT horizon별 차이
- DIRECT vs RECLAIM 차이
- 저변동+보합 분류 여부별 차이

고정 TP와 고점 연동 TP를 **counterfactual 연구**로 비교하고, 충분한 표본 전에는 실제 청산정책을 바꾸지 않는다.
