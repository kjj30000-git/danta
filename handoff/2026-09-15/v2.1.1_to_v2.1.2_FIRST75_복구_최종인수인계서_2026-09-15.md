## 1. 배경: 왜 복구가 필요한가

### 1.1 v1.7.1.3의 기존 구조

기존 `maybe_open_pre_history()`는 하나의 PRE_HISTORY 계통 안에서 다음을 구분했다.

- 최초 75점 도달 시 기존 PRE_HISTORY 사전조건까지 PASS → `pre_entry_type="FIRST_75_PASS"`
- 최초에는 FAIL / DATA_UNAVAILABLE 등이었으나 이후 조건 충족 → `pre_entry_type="LATER_PASS"`

기존 실제매매 gate도 `pre_entry_type == LIVE_ENTRY_MODE`를 통해 `FIRST_75_PASS`만 실제 진입 대상으로 연결했다.

이 FIRST/LATER 판정 의미 자체는 기존 전략의 연속성을 위해 보존해야 한다.

### 1.2 v2.0 전환 시 생긴 회귀

v2.0 연구전용·다중전략 전환에서 설정은 다음처럼 분리됐다.

```python
FIRST_75_RESEARCH_ENABLED = True
LATER_PASS_RESEARCH_ENABLED = False
```

하지만 실제 실행부는 대략 다음 형태로 남았다.

```python
if FIRST_75_RESEARCH_ENABLED:
    maybe_open_pre_history(stock, signal_time)
```

`maybe_open_pre_history()` 내부는 FIRST와 LATER를 모두 생성할 수 있는데, `LATER_PASS_RESEARCH_ENABLED=False`가 내부 LATER 생성 차단에 실제 사용되지 않았다.

따라서 설정상 LATER OFF와 실제 동작이 불일치했다.

### 1.3 CALM 계통의 의미 불일치

원래 합의한 `CALM_FIRST_75` 정의는 다음이다.

```text
FIRST_75_PASS
AND 0.05% <= price_change_30s <= 0.60%
AND price_change_60s <= 1.70%
AND high_gap_change_60s > -0.40%p
```

즉 반드시 **확정된 FIRST_75_PASS의 부분집합**이어야 한다.

현재 구현은 `first_75_time`과 현재 signal time이 같은지를 이용해 단순히 “최초 75점 순간인가”를 확인한다. 이 방식은 해당 신호가 실제 PRE_HISTORY 조건까지 PASS하여 `FIRST_75_PASS`로 확정됐는지를 부모조건으로 보장하지 않는다.

따라서 CALM 계통도 부모관계를 복구해야 한다.

## 2. v2.1.2에서 반드시 수행할 수정

### 2.1 FIRST_75_PASS 판정 의미 보존

FIRST_75_PASS의 조건값 자체를 새로 설계하거나 튜닝하지 않는다.

- 최초 75점 도달 상태 기록
- 기존 PRE_HISTORY 조건 평가
- 그 최초 시점에서 PASS이면 `FIRST_75_PASS`
- 기존 score / 30초·60초 이력 / precheck 의미 / 시간조건을 임의 변경하지 않음

v1.7.1.3과 동일한 입력에 대해서는 FIRST_75_PASS / non-FIRST 판정이 동일해야 한다.

### 2.2 LATER_PASS OFF를 실제 생성 경로에 연결

현재 기본값은 유지한다.

```python
LATER_PASS_RESEARCH_ENABLED = False
```

판정 결과가 `LATER_PASS`일 때는 다음 원칙을 따른다.

```text
LATER_PASS_RESEARCH_ENABLED == False
→ 신규 LATER_PASS paper trade 생성 0건

LATER_PASS_RESEARCH_ENABLED == True
→ 기존 LATER_PASS 판정 의미대로 생성 가능
```

중요:

- LATER_PASS 함수·상태·과거 CSV 호환구조를 삭제하지 않는다.
- 기본 OFF 상태에서 신규 가상진입만 차단한다.
- 과거 데이터 소급 변경 금지.

### 2.3 CALM_FIRST_75 부모관계 복구

CALM 조건은 **확정된 FIRST_75_PASS 이후에만 평가**한다.

권장 흐름:

```text
최초 75점
  ↓
기존 PRE_HISTORY 조건 평가
  ↓
FIRST_75_PASS 확정
  ├─ 기존 FIRST_75_PASS paper 진입
  └─ CALM 추가조건 평가
        ├─ CALM_FIRST_75
        └─ CALM_FIRST_75_PROTECT
```

FIRST_75_PASS가 아니면 CALM 조건이 수치상 충족되더라도 CALM 신규 진입은 **0건**이어야 한다.

CALM 수치조건은 변경하지 않는다.

```python
CALM_30S_MIN_PCT = 0.05
CALM_30S_MAX_PCT = 0.60
CALM_60S_MAX_PCT = 1.70
CALM_HIGH_GAP_60S_MIN_PCTP = -0.40
CALM_PROTECT_ARM_PCT = 1.00
CALM_PROTECT_FLOOR_PCT = 0.40
```

### 2.4 추적 필드의 의미 보존

최종 분석에서 FIRST와 LATER를 혼동하지 않도록 기존 `pre_entry_type` 의미를 끝까지 보존한다.

최소 요구:

- FIRST_75_PASS 결과는 `pre_entry_type="FIRST_75_PASS"`로 식별 가능
- LATER_PASS 결과는 `pre_entry_type="LATER_PASS"`로 식별 가능
- CALM 결과는 자신이 어느 FIRST_75_PASS 신호에서 파생됐는지 재구성 가능

단, 이번 최소 핫픽스에서 대규모 CSV 스키마 재설계는 금지한다. 기존 필드 전달로 충분하면 새 컬럼을 무리하게 늘리지 않는다.
