## 4. v2.3.3 확정 구현사항

### 4.1 박스별 필수 상태

각 장기 보합 박스는 최소한 다음 값을 지속 저장하고 재시작 때 복구한다.

- `box_id`
- `stock_code`, `stock_name`, `trade_date`
- `base_start_time`: 해당 박스 계산에 포함된 첫 정상 완료봉 시각
- `base_ready_time`: 보합 조건이 최초로 성립한 완료봉 시각
- `initial_ready_duration_min`: 최초 성립 평가구간
- `base_high`, `base_low`
- `current_status`
- `terminal_status`, `terminal_time`, `terminal_reason`
- 이미 발송한 지속시간 milestone 집합
- breakout watch·확정 시각

기존 필드와 원장은 삭제하거나 의미를 바꾸지 않는다. 신규 필드는 append-compatible하게 추가한다.

### 4.2 실제 지속시간 계산

`balance_duration_min`의 기존 평가구간 숫자와 실제 경과시간을 혼용하지 않는다.

- 살아 있는 박스: `cutoff_time - base_start_time`
- 종료된 박스: `terminal_time - base_start_time`
- 과거 30분 누적요약 재구성: 현재시각이 아니라 해당 요약의 `cutoff_time`을 사용한다.
- cutoff 이후 발생한 돌파·종료 사건을 과거 요약에 소급 표시하지 않는다.
- 거래일·세션 경계를 넘기는 시간 차이는 만들지 않는다.

필요하면 append-only event history를 사용해 `cutoff_time` 당시 상태를 복원한다. 최종 상태 한 줄만 보고 과거 요약을 만드는 방식은 금지한다.

### 4.3 상태 우선순위와 종료 의미

사용자 표시용 상태는 아래 우선순위를 지킨다.

1. `BASE_BREAKOUT`이 확정되면 그 박스의 최종 사용자 상태는 돌파완료다.
2. 이후 세션 정리나 내부 cleanup이 있어도 이를 `LOW_BREAK` 또는 `SESSION_END` 종료로 덮어쓰지 않는다.
3. 돌파 전 하단 이탈은 `LOW_BREAK` 종료다.
4. 돌파 전 15:30 도달은 `SESSION_END` 종료다.
5. 부분봉·gap·재접속 첫 봉 등 기존 무효 조건은 기존 한국어 사유로 종료한다.
6. `BREAKOUT_WATCH`에서 유지 실패하면 박스를 종료하지 않고 활성 상태로 되돌린다.

내부 cleanup 기록이 필요하면 별도 사건으로 남기되 `terminal_status`를 변경하지 않는다.

### 4.4 지속시간 milestone 알림

같은 `box_id`에 대해 60·90·120·150·180·210·240분 도달 알림은 각각 최대 1회만 보낸다.

- 최초 ready 시 현재 실제 성립 구간을 알린다.
- 최초 성립이 90분이라면 과거 60분 알림을 새로 만들어 소급 발송하지 않는다.
- 이후 같은 박스가 다음 milestone을 충족할 때만 즉시 발송한다.
- 재시작 후 이미 보낸 milestone을 다시 발송하지 않는다.
- 단순 종료는 즉시 별도 알림을 보내지 않고 다음 30분 누적요약에 표시한다.
- 돌파 watch·돌파확정의 기존 즉시 알림 의미는 유지한다.

### 4.5 30분 누적 Telegram 표시

09:30~15:30 매시 30분 일정, 전략별 별도 말풍선, 기존 발송 순서는 변경하지 않는다. 장기 보합 말풍선에서 각 항목은 cutoff 시점 기준으로 다음 중 하나를 명시한다.

- 활성: `보합 N분째 / 최초완성 M분`
- 돌파대기: `보합 N분째 / 최초완성 M분 / 돌파대기`
- 돌파완료: `돌파완료 HH:MM / 총 N분`
- 종료: `보합종료 HH:MM / 총 N분 / 사유: <한국어 사유>`

종목명·6자리 코드·최초 신호시각 등 기존 가독성 규칙은 유지한다. 같은 종목에 여러 `box_id`가 생겼을 때 하나로 합쳐 표시할지 별도 행으로 표시할지는 아직 확정하지 않았으므로 v2.3.3에서 새로운 표시정책을 임의 도입하지 않는다. 기존 `(stock, kind)` 요약 호환을 지키면서 원장과 상태에서는 박스별 이력을 잃지 않아야 한다.

### 4.6 재시작 복구와 outbox

- 상태 checkpoint에는 박스 식별자, 시간, 고정 경계, terminal 상태, 발송 milestone을 원자적으로 포함한다.
- event ledger와 checkpoint가 불일치하면 append-only 사건을 근거로 보수적으로 복구한다.
- 동일 `box_id + event_type + event_time`의 즉시 알림은 중복 발송하지 않는다.
- 30분 누적요약은 기존 cutoff 기반 outbox key를 유지한다.
- 전송 성공 여부가 불명확한 crash window에서는 기존 중복방지 원칙을 약화하지 않는다.

## 9. 명시적 보류사항

다음은 충분한 표본과 별도 사용자 합의 전까지 구현하지 않는다.

- `고전적 수평 박스` 신규 필터
- range·slope·중심이동·진폭·중첩도 임계값 조정
- OCI홀딩스 한 사례를 정답으로 삼는 튜닝
- 장기 보합 조건을 STRUCTURE·SNAPSHOT 진입에 적용
- 수익률이 좋아 보이는 조건만 선택하는 사후 최적화
- 동일 종목 다중 박스를 Telegram에 합칠지 분리할지에 대한 신규 정책
- 단순 종료의 즉시 Telegram 알림
- 실제 주문 또는 키움 모의주문 연결

향후 보합 모양 개선 연구는 최소 3~5거래일, 가능하면 20개 이상의 독립 후보 episode를 모은 뒤 시작한다. 각 episode를 예컨대 `A: 좁고 수평`, `B: 계단형 추세`, `C: 고진폭 왕복`처럼 사람의 시각판정과 수치 feature로 함께 라벨링하고, 특정 종목이 아닌 날짜 분리 out-of-sample로 검증한다. 이 연구계획은 v2.3.3 구현사항이 아니다.
