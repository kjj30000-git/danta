# v2.3.5 독립 2차 비판적 리뷰

검토일: 2026-11-15 KST. 별도 리뷰어가 최신 인수인계서와 후보의 실제 운영 호출·저장·복구·성과 경로를 독립 점검했다. 작성자의 테스트 결과를 전제로 PASS하지 않았다.

## 초기 판정

**FAIL — 최초 후보는 릴리스 불가.** 아래는 최초 구현에 대한 발견이다. 수정 후 재검증 판정과 구분한다. 검토 중 키움 실서버 접속·실제·키움 모의주문을 실행하지 않았다.

## 독립 probe 결과

최초 후보의 engine을 독립 namespace와 임시 SQLite에서 실행했다. broker·network는 사용하지 않았다.

- ACK 이벤트를 process에 넣은 뒤: `candidate.subscription_ok = None`, subscriptions `{}`.
- 09:00:00부터 09:05:00까지 매초 유효 KRX 체결을 제공한 뒤: `OPENING_RANGE_INCOMPLETE`, 연속 유효봉 4개, `RANGE_READY` 0개.
- 정상 −10010/−10000 호가: `QUOTE_UNAVAILABLE / QUOTE_FIELD_TIME_OR_SESSION`.
- B READY에서 재연결 gap을 제공한 뒤: READY 유지. 첫 사건 연속성 증명 실패.

이 probe의 목적은 최초 구현에서 실제 결함이 드러나는지 보는 것이다. 테스트 helper로 신규 구독 gate를 강제로 True로 만들거나, 최초5분 유효봉을 운영경로 바깥에서 주입하여 위 결함을 숨기지 않는다.

## 수정 후 독립 확인

수정 후보를 다시 읽고 `reports/inspection/v2.3.5_independent_probes.py`의 서로 다른 10개 반증 시험을 추가했다. 모두 PASS했다.

1. 실제 가상거래 이익과 현금 증가를 계좌수익률이 동일하게 보고한다.
2. 최초 신호 후 정상 완료봉은 `TERMINAL_ALREADY_SIGNALLED`이며 가짜 결측으로 누적되지 않는다.
3. 재연결 후 이전 ACK를 버리고 새 ACK를 받아야 한다.
4. 09:05 이후 부분봉은 B 최초사건 자료를 무효화한다.
5. KRX 원시 완료봉과 REST OHLCV가 불일치하면 참조범위를 초기화하지 않는다.
6. SQL 저장실패 뒤 재저장해도 사건은 정확히 한 번이며, 5개 CSV 전체 행 수가 일관 backup DB와 일치한다.
7. rank 응답의 한 개 비정상 행은 다른 정상 행의 후보 생성을 막지 않는다.
8. 남은 활성슬롯은 과거 삽입순이 아니라 현재 rank 우선순위에 따라 배정한다.
9. 청산 미확정 FILL을 실험 전체 원장에서 찾아 결과표에 표시하고 수익성 PASS를 차단한다.
10. 정상 수신된 등락률·거래대금이 진입조건에 못 미치는 경우를 데이터 결측으로 오분류하지 않는다.

작성자 검증 25개도 별도 프로세스에서 다시 실행해 PASS했다. 이 실행의 처리속도는 20종목×매초 체결/호가의 2,400 raw 이벤트를 0.766초(약3,132이벤트/초)에 처리했다. 마지막 참조계약 보강 뒤 B 양성 운영경로 시험도 다시 실행해 PASS했다. 이는 해당 합성 1Hz 입력 시험의 결과이며, 실제 장중 최고부하·네트워크·디스크 지연 검증을 대신하지 않는다.

공개 KOSPI 종목 master의 실제 ZIP(sha256 `19de09a78b79d8bc304536a9029410f47dee68e25e0fb9b9975d55f0c05800c9`)도 별도로 읽었다. 파서는 2,118레코드·보통주801개를 반환했고 삼성전자/네이버는 보통주, 삼성전자우는 우선주, KODEX200은 ETF로 구분했다. 이 확인은 로그인 없는 정적 파일 조회이며 키움 broker/주문 호출이 아니다.

### 재검토 중 발견한 추가 운영 경계

- 잠금 역전: engine lock→manager lock과 manager lock→engine lock의 경합을 제거하도록 전달했고 수정된 lock 배치를 확인했다.
- Telegram/CSV 때문에 시세 worker가 잠기지 않도록 외부 I/O를 분리했다. exporter는 별도 연결의 SQLite backup snapshot만 읽고, 같은 snapshot의 CSV와 backup을 대조하는 구조로 수정됐다.
- 확인된 제외상품은 active/평가 분모에서 제외하고, 신규 ACK 분기·KRX 구독 연결·부호 가격·넓어진 spread 청산·지수 전체상태 직렬화·동일신호 paired 계정·조기청산 뒤 PATH를 수정한 것을 확인했다.
- 마지막 재검토의 **포화 시 보유시세 우선 수용**은 관찰용160·보호대상 예약40의 공용200 상한으로 수정됐고, **새 프로세스에서 DB 복원된 v234/v235 포지션의 최초 구독 복구**는 bootstrap의 우선순위 복원·등록 경로로 수정됐다. 작성자 회귀의 용량·복원 시험과 수정된 호출 경로를 대조했다.
- 가용성 계산에서 terminal·warmup·확정 제외상태를 분리하고, 모든 날짜의 FILL−완전 EXIT를 대조하여 미확정 거래가 성과표에서 검열되지 않도록 수정했다. 참조봉 API는 서로 다른 형태의 raw 완료2봉이 OHLCV까지 정확히 겹치는 경우에만 사용한다. 겹침을 확인하지 못하면 B는 평가불가다.

부모 보존 독립 AST대조: 이름에 `live|broker|order|buy|sell|exit_cache`가 포함된 top-level 64개 정의의 변경은 0개이고, 부모 전체 top-level 정의의 누락도 0개였다. 개별 AST 해시는 `v2.3.5_parent_core_preservation.json`에 기록했다. WebSocket manager 클래스의 변경은 이 동결 정의 집합과 구분했다.

python reports/inspection/v2.3.5_independent_probes.py

## 최종 독립 판정

**정적·격리 검증 범위에서 PASS.** 이번 리뷰에서 찾은 release 차단 결함의 수정과 독립 반증 시험을 확인했다. 검토 후보 SHA-256은 `75a8ccdf3b2c3f45374f4959c239545ed74a49fd66eb6427756e207fb8d1b409`다. 코드가 달라지면 그 최종본으로 전체 회귀를 다시 실행해야 한다. 이 판정은 수익성 통과·실제 주문·키움 모의주문 승인이 아니다.

최종 알림 형식 보완도 재검토했다. 종목명·종목코드 단독 줄, 신호/검출/가상체결 시각, 신호가/가상체결가, 설정에서 가져오는 TP·SL, 지수상태, 연구용 가상진입·실제주문 없음 안내가 분리되어 있다. outbox 키와 발송 상태전환은 그대로다. 이 변경 뒤 독립10개 시험을 다시 실행해 모두 PASS했고 release와 candidate 파일이 byte 단위로 일치함을 확인했다.

## 실제 서버 잔여 확인

정적·mock 통과는 키움 실제 ACK 순서·호가 필드 실수신·실제 체결을 확인한 결과가 아니다. 공개 master의 당일 제공·고정폭 파서, 완료분봉 시각 의미, 구독수 산정의 서버 정의도 검증근거와 미확정을 분리해야 한다. 미확정 필수 입력은 평가불가이며 임의 보완해 신호를 만들지 않는다.
