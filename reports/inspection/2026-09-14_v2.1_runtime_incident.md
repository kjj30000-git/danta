## 1. 확인된 P0 결함

### 1.1 `copy` import 누락

v2.0과 v2.1은 `copy.deepcopy()`를 사용하지만 `import copy`가 없다. 이 결함은 실제 장중
사용되지 않은 v2.0에서 유입됐고 v2.1이 그대로 승계했다. v2.1의 OPENING_LEADER에서도
같은 이름을 추가 사용했다.

장중 로그에서 09:00:02~09:16:01 동안 다음 오류가 62회 발생했다.

```text
메인루프 오류: name 'copy' is not defined
```

영향:

- OPENING_LEADER 관찰 파일 미생성
- OPENING_LEADER 판단·진입 0건
- 09:00~09:15 핵심 관찰창 전체 소실
- ORB 유니버스 초기화 실패
- 09:00 ETF 기준 데이터 누락과 후속 `DATA_UNAVAILABLE`

이는 신호 0건이 아니라 수집 실패다.

### 1.2 `selected_exit_strategies` 미정의와 선택 grid 미적용

`open_paper_trade(..., exit_strategies=None, ...)`는 인자를 받지만 실제 전략 생성 시 항상
`EXIT_STRATEGIES` 169개를 사용한다. 마지막 로그에서 정의되지 않은
`selected_exit_strategies`를 참조한다.

영향:

- 종목 후처리 오류 571회
- 메인루프 전파 55회
- 신규 주식 전략이 의도한 20 grid가 아니라 169 grid로 생성
- ETF도 진입했다면 의도한 16 grid가 아니라 169 grid로 생성될 위험
- 포지션을 먼저 등록한 뒤 예외가 발생하여 호출자 관점의 성공/실패가 불일치
- v2.1 거래 결과 105,794행과 연구 부하 증가

이 결함도 v2.0에 이미 존재했으며 v2.1이 승계했다.

### 1.3 운영시간 설정 이중 정의

사용자 설정 셀의 `PROGRAM_START="08:50"`, `PROGRAM_END="15:30"`가 본체에서 다시
`08:00`, `20:00`으로 덮어써진다. 실제 실행값과 사용자가 확인하는 설정값이 분리되므로
단일 설정원칙에 위배된다.

## 3. 기존 검증이 실패한 이유

1. 테스트 프로세스가 먼저 import한 `copy`가 release 누락을 가렸다.
2. 저장소 자동 workflow가 v1.6.8에 머물러 v2.0/v2.1 정적검사를 강제하지 않았다.
3. 실제 시각 guard 때문에 장외 일반 실행은 09:00 전용 분기를 호출하지 않았다.
4. `open_paper_trade()`의 상태 등록만 확인하고 예외 없는 최종 반환과 grid 수를 함께 확인하지 않았다.
5. v2.0이 장중 사용되지 않아 부모 결함이 실행 데이터로 드러나지 않은 채 v2.1의 부모가 됐다.
