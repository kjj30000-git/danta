## 요약

1. 신규 STRUCTURE/SNAPSHOT 전략은 가상진입과 기록된 SIGNAL 모두 0건이다. 따라서 이번 하루 결과로 신규전략의 성과를 평가할 수 없다.
2. 텔레그램 전송 실패가 신규알림 부재의 직접 원인이라는 증거는 없다. 상태파일의 기존 BASE/FIRST_75 알림은 30건 모두 `SENT`였고, 신규 전략 신호·체결은 0건이다.
3. 신규전략 무신호의 직접 원인은 코드 결함이다. 9,526개 완료봉이 전부 무효 처리되어 고점 H, L1, 구조 및 SNAPSHOT 조건을 정상 평가하지 못했다. 따라서 “시장에 조건 충족 종목이 없었다”는 결론을 내릴 수 없다.
4. 연구 큐·기록 writer 부하는 낮았다. 반면 전체 로그의 시장 스캔 간격은 중앙값 약 19초로, 설계상 15초 주기보다 느렸다.
5. 기존 기준 전략은 한 거래일의 소표본에서 약했다. 대표 조합 T250_S150의 비용 차감 평균은 BASE −0.543%, PRE_HISTORY(FIRST_75 계통) −0.406%였다. 실전 판단이나 전략 폐기 결론을 내릴 표본은 아니다.

## 1. 전략 평가

### 신규 v2.3.0 전략

| 확인 항목 | 결과 |
|---|---:|
| BASE 후보 등록 | 17종목 |
| FIRST_75 후보 등록 | 6종목 |
| STRUCTURE 신규 SIGNAL / paper FILL | 0 / 0 |
| SNAPSHOT_DIRECT 신규 SIGNAL / paper FILL | 0 / 0 |
| SNAPSHOT_RECLAIM 신규 SIGNAL / paper FILL | 0 / 0 |
| 신규전략 알림 outbox 항목 | 0 |
| 저장된 신규 SIGNAL 원장 | `pullback_structure_signals_v230.csv` 없음 |
| 저장된 SNAPSHOT 평가 원장 | `pullback_snapshot_evaluations_v230.csv` 없음 |

직렬화된 종료 상태에서도 전략별 신호 수는 BASE 17, FIRST_75 6, SUPPORT/RECLAIM·STRUCTURE·SNAPSHOT 신규전략은 각각 0이었다. 알림 outbox 30건은 모두 `SENT`이며 미확인 전송은 없다. 따라서 확인 가능한 사실은 **새 전략 신호/가상진입이 저장되지 않았다**는 것이다. “신호가 있었는데 Telegram만 누락됐다”고 볼 근거는 없다.

코드 설계상 개별 신규전략 알림은 paper FILL 뒤 outbox에 등록된다. 즉 알림이 오려면 전략 SIGNAL, 다음 정상 tick의 FILL, outbox 등록, worker 전송이 순서대로 성공해야 한다. 이번 자료에서는 첫 단계의 신규 SIGNAL이 0건이라 개별 알림도 만들어지지 않았다.

### 신규전략 무신호의 확정 원인

신규전략에는 17개 관찰 후보가 등록됐지만, 후보별 완료 1분봉 9,526개가 모두 무효 처리됐다. `pullback_metrics_v230.csv`의 모든 샘플에서 `bars == invalid_bars`이고 최종값은 각각 9,526이다. 종료 상태에서도 17개 후보 모두 `high=null`, `L1=null`, `history=0`, `data_status=DATA_UNAVAILABLE`다. 이는 단순 계측 표시 문제가 아니라 구조 상태가 실제로 한 번도 누적되지 않았음을 뜻한다.

코드 경로를 대조하면 원인은 다음과 같다.

1. `v220_on_tick()`은 매 tick마다 `v230_init_candidate(c)`를 호출한다.
2. `v230_init_candidate()`는 후보에 `next_bar_partial` 키가 없으면 기본값 `True`를 다시 넣는다.
3. 새 1분봉을 만들 때 `c.pop('next_bar_partial', False)`로 키를 제거하지만, 같은 분의 다음 tick에서 초기화 함수가 이를 다시 `True`로 만든다.
4. 다음 분봉을 만들 때 다시 생긴 `True`가 소비되어 새 봉의 `valid`가 항상 `False`가 된다.
5. `v220_complete_bar()`는 무효봉이면 `invalid_bars`를 올리고 history를 비운 뒤 H/L1/구조/SNAPSHOT 계산 전에 반환한다.

sequence gap 누계는 17건뿐이고 대부분 장 마감 뒤에 증가했으므로 9,526개 전부가 무효화된 현상을 설명하지 못한다. queue drop/coalesce도 0이었다. 실행 결과와 코드 결함의 결과가 정확히 일치한다.

따라서 이번 자료로는 실제 가격이 1.50% 눌림과 후속 구조 조건을 충족한 종목 수를 계산할 수 없다. 후보별 tick 또는 1분 OHLC 원장이 저장되지 않았기 때문이다. 확인 가능한 결론은 **시장 조건 미충족이 아니라 봉 유효성 상태관리 오류로 신규전략 평가가 차단됐다**는 것이다.

### 시작 지연과 스캔 주기

시스템 CSV에는 07:25:29와 07:35:29 두 번의 시작 배너가 있다. 토큰 발급은 두 번째 배너 후에야 기록된다. 이전 화면의 버전 고정 assertion 오류와 시간상 맞물리므로 첫 실행은 시작 검증 단계에서 멈춘 뒤 재실행한 것으로 보인다. 첫 실패 원인은 화면에서 확인되지만, CSV 자체에는 traceback이 없다.

시스템 로그의 `[SCAN 품질]` 2,176개 기록을 모두 보면 처리시간은 중앙값 약 19초, 최대 28.1초였다(전체 NXT/MAIN/시간외 스캔 포함). 설계 기준 15초보다 실제 처리주기가 길어질 수 있다. 장초반 신호 포착에서는 다음 실행도 MAIN 구간만 따로 집계해 지연 분포를 비교해야 한다.

KA10001 품질 로그는 50,874회 요청·50,863회 성공·11회 실패로 합산됐다. 그중 429 5회, timeout 4회가 기록됐다. 오류 비율은 작지만 호출은 대량이며 429/timeout이 재발하는지 계속 확인할 필요가 있다.

### 데이터 무결성 이슈

1. 저장소 폴더에 `pullback_structure_signals_v230.csv`와 `pullback_snapshot_evaluations_v230.csv`가 없다. 신규 전략 평가의 핵심 근거가 빠졌다.
2. `pullback_metrics_v230.csv`의 684개 샘플에서 `bars == invalid_bars`이며 최종값은 9,526/9,526이다. 이는 `next_bar_partial`이 매 tick마다 다시 생성되는 상태관리 결함과 일치한다.
3. 종료 상태의 후보 17개 모두 history, high, L1이 비어 있다. 신규전략은 장중 가격구조를 한 번도 정상 누적하지 못했다. 후보별 minute 원장도 생성되지 않아 당시 가격으로 반사실적 재평가를 할 수 없다.
4. 현재 main 최신 커밋 `cfe9966058d6c779166297fff6981ae46230c0a7`에는 데이터 파일들이 추가됐지만 `code/releases/027_260923_v2.3.0.ipynb`가 삭제(removed)로 기록돼 있다. README/CURRENT는 여전히 해당 release를 가리킨다. 분석용 코드는 삭제 전 커밋 `f6cb94bf6cd0aaefc290e3168912ee1526d5c7d8`의 파일을 기준으로 대조했으며, 저장소의 현재 코드 경로와 문서 상태가 서로 맞지 않는다.

## 다음 실행 전 우선 조치

1. GitHub main에서 삭제된 v2.3.0 release 파일과 README/CURRENT의 경로를 정합화한다.
2. `next_bar_partial`을 후보 초기 생성·복구 시에만 설정하고, 매 tick 초기화에서 제거된 플래그가 재생성되지 않게 수정한다.
3. 정상 연속 tick으로 2개 이상의 유효 완료봉이 생성되고 `bars > invalid_bars`가 되는 회귀 fixture, 최초 부분봉 fixture, 실제 sequence gap fixture를 각각 검증한다.
4. 실행 결과 업로드 시 신규 SIGNAL·SNAPSHOT 원장 파일이 생성됐는지 확인한다. 0건이어도 헤더가 있는 빈 파일과 전략별 `NO_SIGNAL` 원인 집계를 남긴다.
5. 후보별 완료봉 원장을 반드시 저장하고 유효봉 수, gap 시각·사유, L1 생성/무효화, 각 SNAPSHOT 판정 및 이유를 기록해 후보 lifecycle을 재구성 가능하게 한다.
6. 다음 실행에서는 시작 5분 이내 `bars > 0`, `invalid_bars < bars`, 후보 하나 이상의 `high != null`을 자동 검증한다. 실패하면 신규전략 연구를 중단하고 오류 알림을 보낸다.
7. MAIN 스캔 주기·429/timeout·WebSocket 재연결 후 후보 복구를 계속 확인한다. 유효 데이터가 다시 수집되기 전 신규전략 조건을 완화하지 않는다.

## 계산 방법과 주의

- 고유 진입 수는 `trade_id` 기준으로 센다. TP/SL 조합별 행 수와 혼동하지 않는다.
- 기준 결과는 `entry_mode + TP + SL`로 필터링하고, 비용 차감 수익은 `return_rate − 0.24%p`로 계산했다.
- Net PF는 비용 차감 수익의 양수 합을 음수 수익 절대값 합으로 나눴다.
- net 승률은 비용 차감 후 수익이 0% 초과인 진입 비율이다.
- 신규 전략 0건은 성과가 0%라는 뜻이 아니라 평가 표본이 없다는 뜻이다.
- 본 분석은 가상매매 기록이다. 실제 broker 체결·계좌 수익의 증거로 보지 않는다.
