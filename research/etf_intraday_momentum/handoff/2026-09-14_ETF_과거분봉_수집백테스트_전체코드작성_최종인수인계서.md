## 1. 목적과 연구 배경

Gao, Han, Li, Zhou(2018), `Market Intraday Momentum`의 핵심 가설은 미국 시장에서 전일 종가 대비 첫 30분 수익률이 같은 날 마지막 30분 수익률을 예측하는지 검증하는 것이다. 이를 한국시장 성과로 간주하지 않고 KOSPI·KOSDAQ 지수와 관련 ETF의 과거 1분봉으로 별도 검증한다.

현재 v2.0 장중 ETF 연구는 다음 국내 변형을 전향 수집한다.

- 09:00→09:30 방향
- 09:00→14:30, 14:50, 15:00 누적 방향
- 두 방향이 모두 양수면 LONG, 모두 음수면 INVERSE, 불일치하면 SKIP
- 각 진입시각은 독립 counterfactual
- 15:20 TIME_EXIT
- TP `[0.30, 0.50, 0.75, 1.00]` × SL `[-0.20, -0.30, -0.50, -0.75]` = 16개 grid

과거 백테스트에서는 위 **현재 v2.0 규칙**과 함께 논문에 더 가까운 **원형 규칙**도 분리해 계산한다. 두 규칙의 결과를 섞지 않는다.

## 3. 공식 키움 API

### 3.1 지수 분봉

- API ID: `ka20005`
- API명: 업종분봉조회요청
- URL: `/api/dostk/chart`
- 업종코드: `001` KOSPI 종합, `101` KOSDAQ 종합, `201` KOSPI200

- 출력 최소필드: 체결시간, 시가, 고가, 저가, 현재가, 거래량, 누적거래량

### 3.2 ETF 분봉

- API ID: `ka10080`
- API명: 주식분봉차트조회요청
- URL: `/api/dostk/chart`
- 입력: `stk_cd`, `tic_scope`, `upd_stkpc_tp`, `base_dt`
- 초기 `tic_scope="1"`, `upd_stkpc_tp="1"`
- 출력 최소필드: 체결시간, 시가, 고가, 저가, 종가, 거래량

## 5. 먼저 수행할 데이터 가용성 탐색

전체 수집 전에 `PROBE_ONLY=True` 기본값으로 다음을 확인한다.

1. 최근 정상 거래일 1일의 지수·ETF 1분봉 조회

3. 한 페이지 행 수와 연속조회 종료조건 확인
4. 동일 `base_dt` 연속조회가 전일로 넘어가는지 확인

## 8. 백테스트 규칙

### 8.1 논문 원형에 가까운 규칙

- 첫 30분 수익률은 가능하면 `전일 종가→09:30`으로 계산한다.
- 마지막 30분 구간은 한국 정규장에 맞춰 별도 명시한다.
- 전일 종가 결측 시 당일 시가로 대체하지 않고 해당 규칙을 `DATA_UNAVAILABLE` 처리한다.

### 8.2 현재 v2.0 국내변형 규칙

- `morning_return = price(09:30) / price(09:00) - 1`
- `cumulative_return = price(entry_time) / price(09:00) - 1`
- 둘 다 양수: LONG, 둘 다 음수: INVERSE, 그 외 SKIP
- `entry_time ∈ {14:30, 14:50, 15:00}`는 각각 독립 정책
- 신호에는 해당 시각 이후 데이터 사용 금지
- 진입가격은 해당 시각 이후 실제로 알 수 있는 가격을 사용하도록 보수적으로 정의한다.
- 청산은 TP/SL 또는 15:20 중 먼저 발생한 조건
- 한 1분봉에서 TP와 SL이 모두 접촉하면 순서를 알 수 없으므로 기본값은 보수적으로 SL 우선 처리하고 `AMBIGUOUS_BAR=True`를 기록한다.
- INVERSE는 별도 shadow 성과로 구분한다.

### 8.3 비용

- gross와 net을 모두 저장한다.
- 주식 왕복비용 0.24%를 ETF에 자동 적용하지 않는다.
- 과거 호가가 없으면 수수료·세금·슬리피지를 독립 설정값과 버전으로 남긴다.
- 비용 미확정 시 `cost_status=UNCONFIRMED`로 표시하며 net을 확정값처럼 제시하지 않는다.

## 10. 오류·재개·API 안전

- 조회 API만 사용한다.
- 429에는 지수 백오프와 jitter를 적용하고 같은 요청의 무한 재시도를 금지한다.
- 401/403은 토큰을 1회 갱신한 뒤 재시도하며 반복 실패 시 중단한다.
- timeout·502 등은 제한된 횟수만 재시도하고 실패 manifest를 남긴다.
- `cont-yn="Y"`인데 `next-key`가 없거나 같은 키가 반복되면 pagination loop로 판단해 중단한다.
- 원자적 임시파일→replace로 checkpoint와 manifest 손상을 막는다.
- 인터럽트 후 완료된 날짜·페이지부터 재개한다.
- 현재 장중 v2.0보다 별도 프로세스라는 이유만으로 API 호출제한이 사라지는 것은 아니므로 동시실행하지 않는다.
